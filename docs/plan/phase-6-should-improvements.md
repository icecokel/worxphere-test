# Phase 6. Should 개선

[전체 계획](README.md) · 기준: [도전 요구사항](../requirements.md#5-도전-요구사항-should) · 선행: [Phase 5](phase-5-verification.md)

## 목표

Must 완료 상태를 유지하면서 남은 Should 다섯 항목을 독립적인 feature-key와 커밋으로 구현·검증한다. 범위 밖 기능, 새 상태 관리 계층과 성능 문제가 확인되지 않은 선제 최적화는 추가하지 않는다.

## 완료 기준

- [ ] 같은 지원자의 빠른 연속 변경에서 PATCH가 중복되거나 화면·저장 상태가 어긋나지 않는다.
- [ ] 1,000건에서 검색·필터와 컬럼 스크롤을 측정하고, 병목이 확인된 경우에만 최소 성능 개선을 적용한다.
- [ ] 마지막으로 성공한 비종료 단계 변경을 한 번 실행 취소할 수 있고, 취소 저장 실패 시 변경 후 단계로 복구한다.
- [ ] 낙관적 업데이트와 롤백의 핵심 상태 로직을 최소 `node:test`로 검증한다.
- [ ] 키보드만으로 카드 선택, 상세 열람, 단계 변경 확인과 취소를 완료할 수 있다.
- [ ] 각 feature-key의 `PROMPTS.md` 기록과 개별 커밋이 완료되고 전체 회귀 검증이 통과한다.

## 선행조건과 범위

- Phase 5의 Must 자동·브라우저 검증과 `release-check` 커밋이 완료돼야 한다.
- 각 Task 시작 전 작업 트리에 해당 Task와 무관한 변경이 없어야 한다.
- Task는 아래 순서로 진행하되 각각 독립적으로 완료·커밋한다.
- `최종합격`과 `불합격`은 변경할 수 없는 종료 상태라는 Must 규칙을 유지한다.
- 새 라이브러리를 추가하지 않고 현재 의존성, `node:test`와 브라우저 기본 기능을 사용한다.

## Task 6.1. 단계 상태 로직 검증

- feature-key: `stage-move-test`
- 예상 파일: `src/components/pipeline-board.tsx`, 필요한 경우 최소 순수 상태 모듈, `scripts/check-stage-move.mjs`, `package.json`, `PROMPTS.md`

작업:

- [ ] 낙관적 이동과 실패 복구에 필요한 순수 상태 로직만 컴포넌트 밖으로 분리한다.
- [ ] 이동 시 원본·대상 컬럼의 카드, 인원수와 지원자 단계가 함께 바뀌는지 검증한다.
- [ ] 롤백 시 원래 단계, 인원수와 배열 위치가 복구되는지 검증한다.
- [ ] 존재하지 않는 지원자와 같은 단계 요청이 상태를 변경하지 않는지 검증한다.
- [ ] `pnpm test:stage-move` 스크립트를 추가한다.

검증:

- [ ] `pnpm test:stage-move`
- [ ] `pnpm lint`, `pnpm build`

## Task 6.2. 빠른 연속 변경 경쟁 상태

- feature-key: `stage-move-race`
- 예상 파일: `src/components/pipeline-board.tsx`, `PROMPTS.md`

작업:

- [ ] 같은 지원자의 확인 동작을 빠르게 반복해 현재 구현에서 중복 PATCH가 발생하는지 먼저 재현한다.
- [ ] 한 요청이 시작되는 즉시 같은 지원자의 추가 요청을 동기적으로 차단한다.
- [ ] 성공·실패 응답 뒤 잠금이 해제되고 화면과 브라우저 저장 상태가 같은 단계인지 확인한다.
- [ ] 요청 큐나 범용 동시성 계층은 추가하지 않는다.

검증:

- [ ] 빠른 연속 확인에서도 지원자별 PATCH가 한 번만 발생한다.
- [ ] 성공 후 새로고침 유지와 실패 후 롤백·재시도가 모두 동작한다.
- [ ] `pnpm test:stage-move`, `pnpm lint`, `pnpm build`

## Task 6.3. 키보드 전용 흐름

- feature-key: `keyboard-flow`
- 예상 파일: 기존 보드와 shadcn/ui 컴포넌트, `PROMPTS.md`

작업:

- [ ] `Tab`과 `Enter` 또는 `Space`로 지원자 카드를 선택해 상세 패널을 연다.
- [ ] 상세 패널 안에서 다음 단계·불합격 처리 버튼과 닫기 버튼으로 이동할 수 있게 한다.
- [ ] 확인 모달이 포커스를 가두고 `Escape` 취소와 확정 후 적절한 위치로 포커스를 돌려주는지 확인한다.
- [ ] 기존 shadcn/ui 기본 동작으로 충족되는 항목은 별도 코드 없이 검증 결과만 기록한다.
- [ ] 요구사항에 없는 단축키 체계는 만들지 않는다.

검증:

- [ ] 마우스 없이 상세 열기, 취소, 단계 변경과 패널 닫기를 완료한다.
- [ ] 포커스 링이 보이고 모달·패널 뒤 요소로 포커스가 빠지지 않는다.
- [ ] `pnpm lint`, `pnpm build`

## Task 6.4. 최근 단계 변경 실행 취소

- feature-key: `stage-undo`
- 예상 파일: `src/components/pipeline-board.tsx`, 기존 shadcn/ui 컴포넌트, `PROMPTS.md`

최소 해석:

- 실행 취소는 현재 페이지에서 마지막으로 성공한 단계 변경 한 건만 보관한다.
- Must의 종료 상태 규칙을 우선해 `최종합격` 또는 `불합격`으로 끝난 변경은 실행 취소하지 않는다.
- 일반적인 이전 단계 변경은 계속 제공하지 않고, 실행 취소만 직전 성공 변경의 예외로 처리한다.

작업:

- [ ] 성공한 비종료 단계 변경 뒤 기존 상태 메시지 영역에 `실행 취소` 액션을 표시한다.
- [ ] 실행 취소도 지원자·현재 단계·복구 단계를 기존 확인 모달에서 확인한다.
- [ ] 기존 PATCH를 재사용해 이전 단계로 낙관적으로 복구하고 성공 시 브라우저 저장 상태를 유지한다.
- [ ] 취소 PATCH 실패 시 변경 후 단계로 롤백하고 기존 실패 알림을 표시한다.
- [ ] 실행 취소 완료, 사용자 닫기, 다음 성공 변경 또는 새로고침 시 직전 기록을 제거한다.
- [ ] 여러 단계 이력, 영구 저장과 다중 실행 취소는 추가하지 않는다.

검증:

- [ ] `서류검토 → 면접`과 `면접 → 처우협의` 성공 후 한 번만 실행 취소할 수 있다.
- [ ] 실행 취소 성공은 새로고침 후 유지되고 실패는 변경 후 단계로 복구된다.
- [ ] 최종합격·불합격 상세에는 실행 취소가 제공되지 않는다.
- [ ] `pnpm test:stage-move`, `pnpm lint`, `pnpm build`

## Task 6.5. 1,000건 성능 확인과 최소 개선

- feature-key: `pipeline-performance`
- 예상 파일: 병목이 확인된 기존 보드 코드, `DECISIONS.md`, `PROMPTS.md`

작업:

- [ ] 실제 1,000건 데이터에서 이름 검색, 다중 직무 필터와 각 컬럼 연속 스크롤을 측정한다.
- [ ] 의도된 최대 `800ms` API 지연과 클라이언트 렌더링 시간을 구분해 기록한다.
- [ ] 현재 페이지네이션으로 부드럽게 동작하면 코드 변경 없이 측정 결과와 가상화를 생략한 이유를 기록한다.
- [ ] 재현 가능한 렌더링 병목이 있을 때만 현재 의존성으로 가장 작은 개선을 적용한다.
- [ ] 1,000건을 한 번에 선로딩하거나 새 가상화 라이브러리를 추가하지 않는다.

검증:

- [ ] 1,000건에서 검색·필터 완료 시간과 컬럼 스크롤 상태를 `PROMPTS.md`에 기록한다.
- [ ] 페이지 추가 로드 중 입력과 다른 컬럼 스크롤이 계속 동작한다.
- [ ] `pnpm test:filter`, `pnpm test:pagination`, `pnpm lint`, `pnpm build`

## 예정 커밋

```text
docs(should-plan): Phase 6 Should 개선 계획 추가
test(stage-move-test): 단계 이동과 롤백 상태 검증 추가
fix(stage-move-race): 빠른 연속 단계 변경 중복 요청 차단
feat(keyboard-flow): 키보드 단계 변경 흐름 보완
feat(stage-undo): 최근 단계 변경 실행 취소 추가
perf(pipeline-performance): 1,000건 보드 성능 개선
```

키보드 기본 동작이나 현재 성능이 이미 완료 기준을 충족해 코드 변경이 없다면 해당 feature-key의 검증 문서 커밋만 남긴다.
