# Phase 6. Should 개선

[전체 계획](README.md) · 기준: [도전 요구사항](../requirements.md#5-도전-요구사항-should) · 선행: [Phase 5](phase-5-verification.md)

## 목표

Must 완료 상태를 유지하면서 남은 Should 다섯 항목을 독립적인 feature-key와 커밋으로 구현·검증한다. 범위 밖 기능, 새 상태 관리 계층과 성능 문제가 확인되지 않은 선제 최적화는 추가하지 않는다.

## 완료 기준

- [x] 같은 지원자의 빠른 연속 변경에서 PATCH가 중복되거나 화면·저장 상태가 어긋나지 않는다.
- [x] 1,000건에서 검색·필터와 컬럼 스크롤을 측정하고, 요청 시작·화면 반영 `100ms` 이내와 Long Task `0건`을 확인한 뒤 병목이 있을 때만 최소 성능 개선을 적용한다.
- [x] 마지막으로 성공한 비종료 단계 변경을 한 번 실행 취소할 수 있고, 취소 저장 실패 시 변경 후 단계로 복구한다.
- [x] 낙관적 업데이트와 롤백의 핵심 상태 로직을 최소 `node:test`로 검증한다.
- [x] 키보드만으로 카드 선택, 상세 열람, 단계 변경 확인과 취소를 완료할 수 있다.
- [x] 각 feature-key의 `PROMPTS.md` 기록과 개별 커밋이 완료되고 자동 및 데스크톱 브라우저 회귀 검증이 통과한다.

## 선행조건과 범위

- Phase 5의 Must 자동·브라우저 검증과 `release-check` 커밋이 완료돼야 한다.
- 각 Task 시작 전 작업 트리에 해당 Task와 무관한 변경이 없어야 한다.
- Task는 아래 순서로 진행하되 각각 독립적으로 완료·커밋한다.
- `최종합격`과 `불합격`은 변경할 수 없는 종료 상태라는 Must 규칙을 유지한다.
- 새 라이브러리를 추가하지 않고 현재 의존성, `node:test`와 브라우저 기본 기능을 사용한다.
- Phase 6 브라우저 회귀는 데스크톱 `1024×768`, `1440×900`을 기준으로 하며 모바일·좁은 화면 검증은 범위에 포함하지 않는다.

## 검증 TC

### 공통 준비

- 각 TC는 브라우저 저장 상태를 초기 데이터로 복구하고 새로고침한 뒤 독립적으로 실행한다.
- 경쟁 상태와 롤백 TC는 추적 파일을 수정하지 않는 임시 브라우저 제어로 PATCH 횟수, 지연과 성공·실패 응답을 고정한다.
- 브라우저 TC는 요청 횟수·본문·응답, 화면 단계·컬럼 인원수와 새로고침 결과를 함께 기록한다.
- 실패 재현용 상태와 생성물은 TC 종료 후 제거한다.

### 단계 상태 로직

| ID | 절차 | 기대 결과 |
| --- | --- | --- |
| `SM-01` | 원본 컬럼 중간 위치의 지원자를 다른 컬럼으로 이동한다. | 원본에서 카드가 제거되고 대상 끝에 추가되며, 두 컬럼 인원수와 지원자 단계가 함께 변경된다. |
| `SM-02` | `SM-01`의 이동 결과를 원본 단계와 원래 배열 위치로 롤백한다. | 카드·단계·양쪽 인원수가 이동 전과 같고 카드가 원래 배열 위치로 복구된다. |
| `SM-03` | 존재하지 않는 지원자 ID로 이동과 롤백을 각각 요청한다. | 입력 상태가 변경되지 않는다. |
| `SM-04` | 현재 단계와 같은 단계로 이동을 요청한다. | 카드·인원수·지원자 단계가 변경되지 않는다. |

| `KEY-07` | 최종합격과 불합격 컬럼의 카드 사이를 방향키로 왕복한다. | 두 종료 컬럼도 포커스로 탐색할 수 있고 확인 모달과 PATCH가 발생하지 않는다. |

| `UNDO-03` | 실행 취소 확인 모달에서 `취소` 또는 `Escape`를 사용한다. | PATCH와 화면 단계 변경 없이 직전 실행 취소 액션이 유지된다. |
| `UNDO-04` | 실행 취소 PATCH를 지연된 실패로 고정한다. | 이전 단계가 먼저 표시됐다가 변경 후 단계·인원수·배열 위치로 롤백되고 기존 실패 알림이 표시된다. |
| `UNDO-05` | 실행 취소 가능한 변경 뒤 상태 메시지의 `닫기`를 선택한다. | 직전 기록과 실행 취소 액션이 제거된다. |
| `UNDO-06` | 서로 다른 두 지원자의 비종료 단계 변경을 차례로 성공시키고 실행 취소를 연다. | 마지막으로 성공한 지원자와 단계만 확인 모달에 표시되며 한 건만 되돌릴 수 있다. 새로고침하면 기록만 제거되고 성공한 저장 단계는 유지된다. |
| `UNDO-07` | 실행 취소 가능한 기록을 만든 뒤 다른 지원자의 `처우협의 → 최종합격` 또는 `불합격` 변경을 성공시키고, 초기 최종합격·불합격 지원자 상세도 연다. | 직전 기록이 제거되고 종료 단계 변경에는 새 실행 취소가 생성되지 않으며 최종합격·불합격 상세에도 실행 취소 액션이 없다. |
