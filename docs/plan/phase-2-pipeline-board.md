# Phase 2. 읽기 전용 파이프라인 보드

[전체 계획](README.md) · 기준: [화면 명세](../wireframe.md#2-화면-구조)

## 목표

mock API에서 지원자를 단계별 100개씩 불러와 독립 스크롤되는 5개 고정 컬럼과 지원자 카드로 표시한다. 검색·상세·단계 이동 전에도 로딩, 조회 실패, 전체 빈 상태와 컬럼 빈 상태를 확인할 수 있어야 한다.

## 완료 기준

- [x] `/`에서 정해진 순서의 5개 컬럼과 현재 단계에 맞는 지원자 카드를 표시한다.
- [x] 카드에 이름·직무·지원일·현재 단계를 표시하고, 컬럼 인원수에는 단계별 전체 인원수를 표시한다.
- [x] 로딩, 조회 실패와 재시도, 전체 빈 상태, 컬럼별 빈 상태를 서로 구분해 표시한다.
- [x] 좁은 화면에서는 컬럼 너비를 유지한 채 가로 스크롤되고 shadcn/ui 기본 스타일을 유지한다.
- [x] 각 컬럼은 100개 단위로 조회하고 하단 스크롤 시 다음 페이지를 이어서 표시한다.
- [x] Phase 검증과 `PROMPTS.md`의 `[pipeline-board]` 기록이 완료됐다.

## 선행조건

- Phase 1의 GET API와 지원자 계약이 완료됐다.
- `pnpm build`가 통과한다.

## Task 2.1. 목록 조회와 화면 상태 구성

- feature-key: `pipeline-board`
- 예상 파일: `src/app/page.tsx`, `src/components/pipeline-board.tsx`

작업:

- [x] `/`에서 클라이언트 보드 컴포넌트를 렌더링한다.
- [x] 최초 마운트 시 각 단계에 `GET /api/applicants?stage={stage}&page=1`을 호출한다.
- [x] 응답에 전체 인원수와 다음 페이지 유무를 포함하고 페이지당 최대 100개를 반환한다.
- [x] `loading`, `success`, `error` 상태를 최소 상태값으로 관리한다.
- [x] 로딩 중에는 5개 컬럼 형태의 스켈레톤을 표시한다.
- [x] 조회 실패 시 `지원자를 불러오지 못했습니다.`와 기존 `Button` 기반 `다시 시도`를 표시한다.
- [x] 재시도는 같은 GET 요청을 다시 실행한다.
- [x] 언마운트 후 완료된 요청이 화면 상태를 갱신하지 않게 한다.

공용 UI 선택:

- 기존 `Button`은 그대로 재사용한다.
- 스켈레톤은 기존 구현이 없으므로 필요한 shadcn/ui 구성요소만 추가한다.

## Task 2.2. 보드와 컬럼 레이아웃 구성

- feature-key: `pipeline-board`
- 예상 파일: `src/components/pipeline-board.tsx`, 필요 시 `src/app/globals.css`

작업:

- [x] 헤더에 `채용 파이프라인 보드`를 표시한다.
- [x] 컬럼 순서를 공용 `STAGES` 상수로 고정한다.
- [x] 모든 컬럼을 `288px` 동일 너비, `12px` 간격으로 표시한다.
- [x] 화면 너비가 부족하면 보드만 가로 스크롤되게 한다.
- [x] 각 컬럼의 카드 목록만 세로 스크롤되게 한다.
- [x] 컬럼 하단에 가까워지면 해당 단계의 다음 페이지를 이어서 조회한다.
- [x] 컬럼 헤더에 단계명과 단계별 전체 인원수를 표시한다.
- [x] shadcn/ui `base-nova`, `neutral` 기본 스타일과 기존 semantic token을 유지한다.
- [x] 단계 색상은 점·배지에만 최소로 사용하고 텍스트 단계명을 유지한다.
- [x] 나인하이어의 브랜드 색상이나 장식을 복제하지 않는다.

## Task 2.3. 지원자 카드 구성

- feature-key: `pipeline-board`
- 예상 파일: `src/components/pipeline-board.tsx`

작업:

- [x] 지원자를 현재 `stage` 컬럼에만 배치한다.
- [x] 카드 정보 순서를 이름 → 직무 → 지원일 → 현재 단계로 맞춘다.
- [x] 지원일을 `YYYY.MM.DD`로 표시한다.
- [x] 카드는 shadcn/ui Card의 기본 배경, 테두리, 그림자, radius를 사용한다.
- [x] 아직 클릭, 드래그, 저장 동작은 연결하지 않는다.

## Task 2.4. 빈 상태 구분

- feature-key: `pipeline-board`

작업:

- [x] 전체 데이터가 없으면 컬럼 헤더를 유지하고 `등록된 지원자가 없습니다.`를 표시한다.
- [x] 다른 컬럼에 카드가 있고 특정 컬럼만 비면 해당 컬럼에 `지원자 없음`을 표시한다.
- [x] 모든 빈 상태에서도 컬럼 인원수는 `0`으로 표시한다.
