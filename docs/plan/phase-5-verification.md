# Phase 5. 통합 검증과 제출 문서

[전체 계획](README.md) · 기준: [완료 확인 기준](../wireframe.md#10-완료-확인-기준)

## 목표

Phase 1~4 결과를 Must 기준으로 통합 검증하고, 제출 문서가 실제 코드와 결과를 설명하도록 정리한다. 이 Phase에서는 새 Must 기능을 추가하지 않는다.

## 완료 기준

- [x] `pnpm lint`, `pnpm build`, `pnpm test:hooks`가 모두 통과한다.
- [x] 브라우저에서 모든 Must 시나리오와 단계 저장 성공·실패 복구를 확인한다.
- [x] `README.md`, `DECISIONS.md`, `PROMPTS.md`가 실제 구현과 검증 결과를 설명한다.
- [x] 미완료 Should 항목은 미구현으로 기록하고 범위 밖 기능을 추가하지 않는다.
- [x] 검증용 임시 변경과 생성물이 남지 않고 release-check 문서 커밋이 완료됐다.

## 선행조건

- Phase 1~4의 각 커밋과 개별 검증이 완료됐다.
- 작업 트리에 해당 Phase와 무관한 변경이 없다.

## Task 5.1. 자동 검증

- feature-key: `release-check`

작업:

- [x] `pnpm lint`

- [x] `pnpm test:hooks`

- [x] 생성물이나 임시 강제 실패 코드가 추적 파일에 남지 않았는지 확인한다.

## Task 5.2. 브라우저 통합 검증

- feature-key: `release-check`

시나리오:

- [x] 최초 진입에서 로딩 후 5개 컬럼과 200건 이상 지원자가 표시된다.
- [x] 각 카드가 이름, 직무, 지원일, 현재 단계를 표시한다.
- [x] GET 실패 화면에서 `다시 시도`가 동작한다.
- [x] 전체 빈 상태, 검색 결과 없음, 컬럼 빈 상태가 구분된다.
- [x] 한글·영문 이름 검색과 직무 필터가 함께 동작한다.
- [x] 200건 이상에서 검색·필터 입력에 체감 지연이 없다.
- [x] 카드 선택, 상세 값, 패널 닫기가 동작한다.
- [x] 상세 패널의 다음 채용 단계와 불합격 처리 섹션이 분리돼 표시된다.
- [x] 정규 다음 단계 또는 불합격 처리 버튼을 누르면 알림 가능성을 포함한 shadcn/ui 확인 모달이 표시된다.
- [x] 중간 단계 건너뛰기와 이전 단계 변경이 제공되지 않고, 불합격 처리는 `서류검토`, `면접`, `처우협의`에서만 제공된다.
- [x] 최종합격 상세 패널에는 불합격 처리 UI가 없고, 해당 API 요청은 `400`으로 거부된다.
- [x] 확인을 취소하면 카드와 PATCH 요청이 변경되지 않는다.
- [x] 확인 직후 카드와 인원수, 상세 값이 먼저 갱신된다.
- [x] PATCH 성공 후 새로고침해도 단계가 유지된다.
- [x] PATCH 실패 시 카드, 인원수, 상세 값이 이전 단계로 돌아오고 알림이 표시된다.
- [x] 좁은 화면에서 보드 가로 스크롤과 상세 패널 전체 너비가 동작한다.

검증 결과는 성공 여부만 적지 않고 실제로 확인한 상태와 실패를 재현한 방법을 `PROMPTS.md`에 기록한다.

## Task 5.4. Should 검토

모든 Must 검증 후 남은 시간이 있을 때만 별도 계획·feature-key·커밋으로 진행한다.

- 같은 지원자의 빠른 연속 변경 경쟁 상태 고도화
- 1,000건 기준 가상화 또는 추가 성능 최적화
- 최근 단계 변경 실행 취소
- 핵심 상태 로직의 최소 `node:test` 검증
- 키보드만으로 단계 이동과 상세 열람

진행하지 않은 항목은 구현하지 않고 `DECISIONS.md`에 이유만 남긴다.
