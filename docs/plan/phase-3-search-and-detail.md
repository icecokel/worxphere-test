# Phase 3. 지원자 탐색과 상세 보기

[전체 계획](README.md) · 기준: [이름 검색](../wireframe.md#42-이름-검색), [직무 필터](../wireframe.md#43-직무-필터), [상세 패널](../wireframe.md#46-지원자-상세-패널)

## 목표

읽기 전용 보드에 이름 검색과 직무 필터를 추가하고, 선택한 지원자의 정보를 우측 패널에서 확인할 수 있게 한다. 검색·필터와 상세 보기는 서로 독립된 기능이므로 별도 Task와 커밋으로 처리한다.

## 선행조건

- Phase 2 보드가 실제 API 데이터와 화면 상태를 표시한다.
- 카드와 컬럼 인원수가 원본 지원자 상태에서 계산된다.

## Task 3.1. 이름 검색과 직무 필터

- feature-key: `candidate-filter`
- 예상 파일: `src/components/pipeline-board.tsx`, 필요한 shadcn/ui 입력·선택 컴포넌트

작업:

- [ ] 검색 입력 레이블을 `이름 검색`, 플레이스홀더를 `지원자 이름 검색`으로 표시한다.
- [ ] 이름은 앞뒤 공백 제거 후 부분 일치로 검색한다.
- [ ] 영문 이름은 대소문자를 구분하지 않는다.
- [ ] 직무 선택 기본값을 `전체`로 표시한다.
- [ ] 직무 선택지는 로드된 데이터에서 중복을 제거해 만든다.
- [ ] 특정 직무 선택 시 정확히 일치하는 지원자만 표시한다.
- [ ] 이름과 직무 조건은 AND로 적용한다.
- [ ] 필터 결과와 컬럼 인원수를 같은 계산 결과에서 만든다.
- [ ] 별도 디바운스·검색 라이브러리 없이 `useMemo`와 표준 배열 메서드를 사용한다.
- [ ] 결과가 없으면 컬럼 헤더를 유지하고 `조건에 맞는 지원자가 없습니다.`를 표시한다.

검증:

- [ ] 한글 부분 검색
- [ ] 영문 대소문자 검색
- [ ] 직무 단독 필터
- [ ] 이름과 직무 동시 적용
- [ ] 입력 초기화 후 전체 복원
- [ ] 200건 이상에서 입력과 필터 변경에 체감 지연이 없는지 확인
- [ ] `pnpm lint`, `pnpm build`
- [ ] `PROMPTS.md`의 `[candidate-filter]` 기록

커밋:

```text
feat(candidate-filter): 지원자 이름 검색과 직무 필터 추가
```

## Task 3.2. 지원자 상세 패널

- feature-key: `candidate-detail`
- 예상 파일: `src/components/pipeline-board.tsx`, 필요한 shadcn/ui Sheet 컴포넌트

작업:

- [ ] 카드를 선택하면 우측 `지원자 상세` 패널을 연다.
- [ ] 선택 상태는 지원자 객체 복사본 대신 `id`로 보관한다.
- [ ] 상세 정보에 이름, 직무, 지원일, 현재 단계만 표시한다.
- [ ] 데스크톱 패널 너비는 `420px`, `640px` 미만은 전체 너비로 표시한다.
- [ ] 닫기 버튼, `Escape`, 바깥 영역 선택으로 닫는다.
- [ ] 카드 선택 요소에 이름을 포함한 접근 가능한 레이블과 포커스 표시를 둔다.
- [ ] 검색·필터로 선택한 지원자가 결과에서 제외되면 패널을 닫는다.
- [ ] 패널을 닫아도 보드 스크롤과 데이터 상태를 유지한다.

검증:

- [ ] 카드별 상세 값 일치
- [ ] 세 가지 닫기 방식 확인
- [ ] 좁은 화면의 전체 너비 확인
- [ ] 필터 제외 시 패널 닫힘 확인
- [ ] `pnpm lint`, `pnpm build`
- [ ] `PROMPTS.md`의 `[candidate-detail]` 기록

커밋:

```text
feat(candidate-detail): 지원자 상세 패널 추가
```

이 Phase에는 단계 변경이나 API PATCH를 포함하지 않는다.
