# Phase 4. 단계 이동과 낙관적 업데이트

[전체 계획](README.md) · 기준: [단계 이동 흐름](../wireframe.md#5-단계-이동과-저장-흐름)

## 목표

브라우저 기본 드래그앤드롭으로 카드를 다른 컬럼에 이동하고, API 응답 전 화면 반영·성공 저장·실패 롤백을 하나의 일관된 흐름으로 구현한다.

## 완료 기준

- [ ] 다른 단계에 드롭하면 카드·컬럼 인원수·상세 패널을 즉시 갱신하고 PATCH 요청을 한 번 보낸다.
- [ ] 같은 단계 드롭과 드래그 취소는 상태 변경이나 API 요청을 만들지 않는다.
- [ ] 저장 성공은 새로고침 후에도 유지되고, 저장 중인 카드는 중복 이동되지 않는다.
- [ ] 저장 실패는 카드·인원수·상세 패널을 이전 상태로 복구하고 오류를 알린다.
- [ ] Phase 검증과 `PROMPTS.md`의 `[stage-move]` 기록이 완료됐다.

## 선행조건

- Phase 3까지의 보드, 필터, 상세 패널이 완료됐다.
- Phase 1의 PATCH API가 성공과 실패를 모두 반환한다.
- 지원자 원본 상태가 한 곳에서 관리된다.

## Task 4.1. 카드 드래그앤드롭

- feature-key: `stage-move`
- 예상 파일: `src/components/pipeline-board.tsx`

작업:

- [ ] HTML Drag and Drop API로 카드의 지원자 ID를 전달한다.
- [ ] 컬럼을 유효한 drop target으로 만든다.
- [ ] 드래그 중 대상 컬럼의 배경과 테두리를 강조한다.
- [ ] 드래그 취소 시 화면 상태를 변경하지 않는다.
- [ ] 원래 컬럼에 드롭하면 상태 변경과 API 요청을 모두 생략한다.
- [ ] 드래그와 짧은 카드 선택을 구분해 상세 패널이 의도치 않게 열리지 않게 한다.
- [ ] DnD 전용 라이브러리는 추가하지 않는다.

## Task 4.2. 낙관적 업데이트와 저장

- feature-key: `stage-move`

작업:

- [ ] 다른 컬럼에 드롭하면 해당 지원자의 `stage`를 화면 상태에서 즉시 변경한다.
- [ ] 변경 직후 `PATCH /api/applicants/:id/stage`를 호출한다.
- [ ] 저장 중인 지원자 ID를 최소 상태로 관리한다.
- [ ] 저장 중 카드는 투명도와 진행 표시를 적용하고 추가 드래그를 막는다.
- [ ] 성공 응답 후 대상 컬럼 위치를 유지하고 저장 중 표시를 제거한다.
- [ ] 상세 패널이 열려 있으면 같은 원본 상태에서 현재 단계를 즉시 반영한다.
- [ ] 검색·필터 결과와 컬럼 인원수도 낙관적 상태를 기준으로 갱신한다.

## Task 4.3. 실패 롤백과 알림

- feature-key: `stage-move`

작업:

- [ ] 요청 전 단계 값을 롤백에 필요한 최소 정보로 보관한다.
- [ ] PATCH 실패 시 해당 지원자의 단계만 이전 값으로 복구한다.
- [ ] 원본 배열 순서를 유지해 이전 컬럼 내 위치도 자연스럽게 복구한다.
- [ ] `단계 변경에 실패했습니다. 다시 시도해 주세요.`를 `role="alert"`로 표시한다.
- [ ] 실패 알림은 사용자가 닫을 수 있고 일정 시간 뒤 제거한다.
- [ ] 실패 후 해당 카드를 다시 이동할 수 있게 한다.
- [ ] 실패 응답은 브라우저 저장소와 성공 상태를 오염시키지 않는다.

## Phase 검증

- [ ] 다른 모든 단계 조합으로 카드 이동
- [ ] 같은 컬럼 drop 시 요청 없음
- [ ] 저장 중 같은 카드 재이동 차단
- [ ] 성공 후 새로고침 시 대상 단계 유지
- [ ] 실패를 로컬에서 강제로 발생시킨 뒤 카드·인원수·상세 패널 롤백 확인
- [ ] 강제 실패 설정을 복원하고 작업 diff에 남지 않았는지 확인
- [ ] 실패 알림의 표시와 닫기 확인
- [ ] 검색·필터 적용 중 이동 결과 확인
- [ ] `pnpm lint`, `pnpm build`
- [ ] `PROMPTS.md`의 `[stage-move]`에 실제 검증 결과 기록

## 커밋

```text
feat(stage-move): 카드 단계 이동과 실패 롤백 추가
```

같은 카드의 다중 요청 순서 제어, 실행 취소, 키보드 DnD는 Should이므로 이 Phase에 추가하지 않는다. Must 범위에서는 저장 중인 카드의 재이동 차단으로 중복 요청을 예방한다.
